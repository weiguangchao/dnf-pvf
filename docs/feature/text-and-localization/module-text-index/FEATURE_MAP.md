# 模块文本索引功能索引

各功能模块的文本编目和字符串引用。

## 功能范围

- 功能模块与字符串资源的索引关系。
- 脚本文本引用与模块文本的对应关系。

## 分类依据

已读取模块字符串索引，包含角色、装备、地图、怪物、NPC、任务、宠物和界面等模块；脚本样本可见按模块编号引用的文本。

## 定位与样本

`output/n_string.lst:2` 保存模块编号与字符串文件路径的交替序列，实测有 26 组。怪物样本 `output/monster/goblin/bombkagel.mob:92` 使用 ``<7::name_595`爆弹卡格`>``，对应值在 `output/monster/monster.kor.str:2917`。

## 参数项与作用

- 模块编号为十进制整数。样本中 0 是角色，3 是装备，7 是怪物，11 是普通任务，12 是技能，13 是可堆叠道具，16 是宠物，17 是 AI 角色。这些映射直接来自当前模块索引，不宜换成其他版本的编号表。
- 模块路径是反引号字符串。例如编号 7 对应 `Monster/Monster.kor.str`。大小写和路径来自封包，磁盘解包位置统一成小写并不代表可任意改写封包路径。
- 任务还有单独的史诗任务文本模块，不能把所有任务引用都硬编码成 11。具体以 `n_string.lst` 中目标模块和脚本的编号为准。
- 文本链接的第一部分 `7` 选择模块，第二部分 `name_595` 选择该模块中的键。相同键名在不同模块下不是同一个文本。
- 链接内的 `爆弹卡格` 是解包器为阅读补上的显示值。`ScriptText.compile` 仅发出模块编号和键，不使用这段显示值。因此只改 `.mob` 链接中的中文并不会改回包后的名称。
- `.str` 使用 `键>值` 行格式。本样本的完整行为 `name_595>爆弹卡格`。第一处 `>` 是键值分隔符，值内部出现的其他 `>` 应属于值。
- `.str` 的注释与值可能使用不同源编码。解包后的文本可为 UTF-8，回包器会参考原条目编码重新写入。不要用反编译脚本的反引号语法包裹整条字符串行。
- `str_text_to_bytes` 在行数和未改内容相同时会保留相应原始行字节。大量重排、统一换行或改动注释会扩大实际重新编码范围。

## 修改步骤

1. 从目标脚本读取实际的模块编号和键，先在 `n_string.lst` 查到对应 `.str`，再确认键的完整拼写。
2. 只修改 `.str` 目标行中第一处 `>` 后的值。保留键、同文件其他行、CRLF 和占位符。若文字含 `%d`、`%s` 或其他格式占位符，应保留调用需要的个数与顺序。
3. 需要换到另一个既有键时，确认该键在源字符串表中，且所选模块确实有对应文本。只存在于 `.str` 而不在全局表中的新键未必能被脚本引用。
4. 回包后重新解析目标 `.str`，并用回包中的文本上下文反编译引用脚本，确认显示值已经改变。测试还应覆盖共享该键的其他界面或对象。

## 未确认与验证

键可能被多条脚本共享，修改名称前必须搜索同模块同键的所有引用。当前编译器不检查所有模块键是否实际存在，能成功编码不代表运行时能解析。修改模块索引本身时，编译上下文仍取自源封包，因此不能依赖同轮编译自动采用新的模块映射。

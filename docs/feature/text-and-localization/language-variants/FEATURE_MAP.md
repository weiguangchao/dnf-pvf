# 语言与地区变体功能索引

语言字符串、地区列表和地区商城配置变体。

## 功能范围

- 语言字符串及地区专用列表。
- 公共配置与地区配置的加载约定。

## 分类依据

已观察到 kor、jpn、chn 语言条目及 jap 商城配置变体。原始国际化说明提到共用列表与国家附加列表，实际变体仍需逐项确认。

## 定位与样本

已读取 `output/lst file control for international.txt` 的 CP949 原文，并对照 `output/character/character.jpn.lst`、`output/character/character.jpn.str`、`output/stagemap/stagemap.chn.str` 和 `output/etc/newcashshop.etc.jap`。这些名称不能合并成一种统一后缀规则。

## 参数项与作用

- 原始说明区分共用列表和国家附加列表，共用列表没有国家后缀。说明列出的韩国、日本、中国后缀分别为 `.kor`、`.jap`、`.chi`。
- 实际封包还存在 `.jpn` 和 `.chn` 命名。不得仅按说明把所有 `.jpn` 改成 `.jap` 或把 `.chn` 改成 `.chi`。加载规则需要以引用和实际客户端为准。
- 原始说明要求国家附加物品和任务列表的编号避免重复，并专门指出商城 IPG 编号和物品编号也不能冲突。它说明了管理约束，没有证明任意两份列表的覆盖优先级。
- `--lang zh-hans` 是解包器的繁简文本转换选择，不是游戏地区选择。`--lang zh-hant` 保留原文，`--raw` 保留原始数据，三者不能当作韩国、日本或中国客户端切换开关。
- 回包应继续使用解包时的语言模式。回包器将磁盘 `.str` 与按当前模式解出的原始内容比较，模式改变可能让未编辑的文字被判定为已改。
- 文本编码按文件及 `.str` 注释和值分别检测，并非看后缀就固定为 UTF-8、CP949 或 Shift-JIS。原样 `.txt`、`.nut` 等条目不经过反编译文本转换。
- 国家商城变体和共用商城配置的标签结构可能不同。原始说明明确提醒它们的标签不同，因此不宜将整块共用配置复制到地区变体。

## 修改步骤

1. 确认目标客户端地区、实际使用的国家配置和当前解包模式，搜索该条目是否被索引或加载入口引用。
2. 同时读取共用项和地区变体，先比较字段结构。只修改目标变体实际包含的字段，不跨格式整块覆盖。
3. 检查编号唯一性和现有键名。换文字时保留原始字符可编码性，原样文件应保留其原编码。
4. 用相同语言参数回包，核对未编辑条目是否意外变化，再在对应地区客户端验证文字、商城与任务。

## 未确认与验证

仓库没有提供客户端地区加载实现。手册不能据后缀推断覆盖顺序，不能承诺只改某地区文件便能改变所有地区。原始说明是设计资料，须与当前封包事实对照。

# 全局字符串表功能索引

全局二进制字符串字典的文档范围。

## 功能范围

- 全局字符串字典及其与脚本文本的关系。
- 字符串内容的编码与读取边界。

## 分类依据

已确认根目录存在全局二进制字符串表。本页依据读取器记录字典边界、字符串下标和编译限制。

## 定位与样本

`output/stringtable.bin` 是二进制资源，不是 #PVF_File 文本。实测长度为 12,784,249 字节，字符串数为 461,796。结构依据来自 `dnf-pvf.py` 的 `load_string_table`、`ScriptText.string_id` 和 `ScriptText.compile`，不是按文件名推断。

## 参数项与作用

- 文件起始 4 字节是有符号小端 int32 字符串数量。本样本为 461796，不能把它当作字节数或最后一个有效下标。有效下标从 0 开始。
- 紧接着是 `count + 1` 个小端 int32 偏移。最后一项是尾部边界，不是一个额外字符串的起始位置。该数组占 `4 * (count + 1)` 字节。
- 数据区起点为 `4 + 4 * (count + 1)`，本样本为 1847192。每个记录的实际字节位置为保存的偏移再加 4。这个偏差由解析代码的边界检查确认。
- 第 0 项偏移为 1847188，第 1 项为 1847218。第 0 字符串的字节区间为 `[1847192, 1847222)`，内容为 ASCII `swordman/kagemaru/kagemaru.aic`。区间右端不包含在该字符串中。
- 尾偏移为 12784245，实际文件末尾为 12784249。所有偏移必须有序并落在数据区边界内。修改一个字符串的字节长度，会影响它后面的所有边界。
- 编码不是全局 UTF-8。读取器会检测 CP950、CP949、Shift-JIS 或 UTF-8 并做语言转换。ASCII 路径样本不能证明所有项使用 ASCII。
- 二进制脚本中类型 5 的段落名、类型 7 的字符串和类型 10 的本地化键通过整数下标引用本表。改变原有条目的下标会影响其他脚本。
- `ScriptText.string_id` 只查源封包已有字符串。当前回包器不收集新字符串，也不自动重建全局表。修改磁盘上的本表不会使同一轮编译改用这份新表。

## 修改步骤

1. 普通属性调整只修改已有脚本的数值。已有枚举、路径或标签可在目标字段允许时复用原字符串表中的条目。
2. 修改显示名称时优先检查对应 `.str`。全局表保存的键或路径不等于用户可见文字。
3. 如需求必须增加标签、键或路径字符串，先扩展编译器的字符串收集与一致性重建能力。当前工具链不支持直接按本页偏移手工插入新条目。
4. 完成工具扩展后，应同时验证所有脚本的字符串下标、表边界、重复字符串处理和回包后的解码结果。

## 未确认与验证

已从读取器确认二进制边界和下标规则。源数据可能有同文不同下标的重复项，不能以文本去重为由随意重排。运行时加载代码并未在仓库提供，因此本页不承诺游戏可以接受任意新增键或枚举。

# 名称索引与编号分区约定功能索引

跨模块名称索引和物品编号分区约定。

## 功能范围

- 名称索引的跨模块组织约定。
- 物品与地区编号分区及唯一性约定。

## 分类依据

已观察到角色技能、物品、怪物、NPC、AI 角色与被动对象的名称索引。原始国际化说明另要求维护编号分区并避免编号重复。

## 定位与样本

已读取 `output/skillname0.lst:2`、`output/monstername.lst:2`、`output/equipment/equipment.lst:2`、`output/equipment/equipmentnumbersection.txt`、`output/stackable/stackablenumbersection.txt` 和国际化说明。名称反查列表与资源列表的字段顺序不同。

## 参数项与作用

- 资源列表以整数 ID 和反引号路径交替。例如装备 ID 10018 对应 `character/common/jacket/cloth/vest_owool.equ`，路径相对于装备资源目录。`.lst` 文件中的所有资源路径不可统一按 `output` 根目录拼接。
- 名称反查列表以反引号名称和整数 ID 交替。例如 `skillname0` 的名称项在前，ID 在后。不能按资源列表的 ID、路径顺序解析它。
- `skillname0` 至 `skillname9` 是多份技能名称反查资源。后缀编号与职业的完整对应表尚未从加载代码确认，不宜只按编号猜测职业。
- 资源 ID 负责跨文件引用，显示名称不是唯一键。物品、怪物、NPC、AI 角色和被动对象的编号分别应到所属列表核对，不能跨系统仅按同一个数字认定是同一对象。
- 名称列表中部分字符串已存在乱码或混合编码的观测结果。不要凭相似读音自动修复全部名称，也不要用显示名称作为批量替换的唯一条件。
- 装备编号分区说明中的韩国 1 至 65535、日本 65536 至 75536 标为原文示例。它们不是当前封包经过核对的完整分配范围。
- 可堆叠道具编号说明仅有国家编号分区的标题，没有已登记区间。空说明不等于任意编号都可用。
- 当前回包器按源目录树重建，只改 `.lst` 并新增磁盘文件不能让新增资源自动进入封包。引用新路径还可能因为原字符串表不存在而编译失败。

## 修改步骤

1. 先明确 ID 所属系统，解析对应列表并检查重复编号。按列表实际的 ID、路径或名称、ID 格式读取。
2. 修改已有对象的属性通常不需要改 ID 或列表。改变引用时，先确认目标 ID 已存在并具有兼容类型。
3. 如需求必须新增资源，先扩展回包器的目录树与字符串表支持，再确定编号分区及同步所有引用。当前工具链不应把改列表当作新增功能的完整流程。
4. 回包后从新目录树查到目标 ID 的资源，并检查反查名称、模块文本及所有关联引用。仅列表文本变化不足以证明资源存在。

## 未确认与验证

地区编号分区和名称反查列表是否被当前版本加载，仍需实际加载证据。本页不为未登记区间分配新 ID，不推定编号唯一性仅限于一个文件。

# 商城分类与购买修改手册

本页用于调整既有商城商品及购买限制。维护者须区分 `etc/newcashshop.etc`、旧商城和 cashshop 中的另一套商品记录。

## 入口与块结构

先搜索商品编号在 `etc/newcashshop.etc` 的出现位置。该文件共 366 行。`cashshop/newarad_cashshop.shp` 共 157 行，编号与内容不同。`cashshop/arad_cashshop.shp:7` 起的五组 item group index 为 `1 2 3 4 99`，各跟一个空 sell item 块，不能仅凭文件名判定当前运行入口。

## 参数与证据

- `[coin]` 在 `etc/newcashshop.etc:9` 至第 15 行。首记录是 ``9000 1 10 0 0 880 <13::name_1`复活币`> 0 0``，共九个 token。最后两个 0 出现在下一物理行开头。共五个九 token 记录，不能逐行当作商品。
- `[item]` 在 `cashshop/newarad_cashshop.shp:11` 至第 40 行。首记录为 ```510491 2675335 1 0 0 1500 <13::name_2675335``> 1 0```。首列推断为商品编号，次列推断为物品引用。数量与价格列需结合客户端确认，不能给两个 0 指定含义。
- `[package]` 在 `cashshop/newarad_cashshop.shp:91` 至第 117 行。首记录 ```510594 2675543 0 0 3990 <13::name_2675543``> 2 0 0 0``` 共十个 token。它与九 token 的 item 记录不同。
- `[cart disallowance]` 在 `etc/newcashshop.etc:334` 至第 336 行，含八个整数 `510656 510655 510654 510698 510912 510921 510940 510941`。标签支持禁止购物车解释，但当前分类中是否仍有对应商品须逐个检索。
- `[gift disallowance]` 在 `etc/newcashshop.etc:338` 至第 340 行，含 `9100`、`10000`、`100200` 等 28 个商品编号。`[cerapoint disallowance]` 和 `[gift only]` 原样为空，见第 342、346 行。空块不等于可删除。
- `[max gift count]` 在 `etc/newcashshop.etc:350` 后接单整数 `10`。标签支持赠送数量上限解释，按订单还是账号计数尚未实测。
- `[not stackable buy]` 在 `etc/newcashshop.etc:352` 至第 354 行列出 17 个编号。推断限制合并购买，不代表物品自身堆叠上限。
- `[account restrict]` 在 `etc/newcashshop_restrict.etc:3` 至第 5 行。第 4 行有 120 个整数，呈十组十二整数。首组 `30008 1 0 2013 3 2 0 2030 4 10 23 50000`。年、月、日、小时解释来自数值形状推断，具体限购周期和最后一列含义未知。`[character restrict]` 在第 7 至 9 行为空。
- `[avatar]` 的 `etc/newcashshop.etc:6` 开头为 `1000000 601550000 3 0 0 -1 -1 601550000 4 0 0 -1`。该形状不同于 coin 和 package，不可套同一列映射。

## 修改步骤与限制

先核实目标编号属于哪套商城，再查所有限制块与 `etc/newcashshop_restrict.etc`。替换既有商品时保持该分类完整记录宽度，连同跨行尾字段一起核对。改限制时用商品编号，不用第二列物品 ID。不得把未证实的 880 写成某种现实货币单位。

回归应覆盖分类显示、直接购买、购物车、赠送和账号限制。文件无法证明服务端是否另有限购规则。日期边界、周期、商品价格倍率仍需运行验证。

## 保存与验证边界

PVF 脚本保留字面头 `#PVF_File\r\n`、CRLF、TAB 和原有 `{1}`/`{3}`、`{6}`/`{8}` 类型。本文中的空格排版不是可覆盖源文件的序列化格式。编译依赖源归档字符串表。只复用已有标记、字符串和路径值。``<module::key`display`>`` 的 display 不参与编译。修改显示文本要定位对应 `.str` 并保留原编码。

交付前逐块比较 token 数量、顺序和引用。完成实际回包后，重新读取目标条目，核对修改值和未改字段。`--verify` 只验证源归档脚本往返，不能证明修改后输出有效。新建 output 文件不会自动入包，删除原有文件会从归档移除。

# 功能索引

本索引沿用现有的 11 类功能分类，提供功能文档的浏览入口。
各子功能通过独立文件夹隔离，并以各自的 `FEATURE_MAP.md` 作为入口。
已按解包条目补充下一级子功能索引。末级索引记录样本定位、具体参数、关联关系和修改步骤。
分类依据来自目录结构、条目名称和抽样字段，按名称推断的用途会单独注明。
条目存在仅表示封包收录，具体数值、规则和运行时启用情况尚未逐项验证。

- [角色与技能](character-and-skills/FEATURE_MAP.md)。角色、职业、副职业、成长和技能。

- [怪物与人偶](monsters-and-ai-characters/FEATURE_MAP.md)。怪物和 AI 角色的属性、行为、动作和攻击。

- [战斗对象与状态效果](combat-objects-and-status-effects/FEATURE_MAP.md)。被动对象、附加状态、属性修正和光环。

- [文本与国际化](text-and-localization/FEATURE_MAP.md)。全局字符串、模块文本索引和国际化约定。

## 维护约定

- 索引文档只链接下一级子功能的索引文档。
- 每个子功能使用独立目录，目录入口统一命名为 `FEATURE_MAP.md`。
- 新增子功能时，先建立目录与索引，再在父级索引中添加链接。
- 功能范围和细分结构在所属目录内维护。
- 上级索引只导航到子功能索引。叶子手册可以用文本路径和行号定位样本，文档链接仍只指向子功能索引。

## 通用修改规则

本手册供后续 agent 定位和修改已有 PVF 条目。叶子页的样本只说明该条目与该字段，不是所有文件通用的完整格式规范。

### 证据等级

- 已观察表示从解包文件读取到的标签、数值、类型、组数或字节结构。
- 代码证据表示可从本仓库的读取器、编译器或原样脚本确认的数据流与格式行为。
- 推断表示根据标签、名称或同类条目归纳的游戏作用。概率分母、时间单位、矩阵列序与未解释的枚举仍需调用方或实机证据。
- 回包验证表示数据能够正确编码和重新读取。它不代表客户端或服务端一定加载该条目，也不代替玩法测试。

### 先识别文件格式

- 反编译脚本以 `#PVF_File\r\n` 开头，按 UTF-8 保存。段落使用 CRLF，数值和字符串使用制表符分隔。读取器与编译器的格式证据在 `dnf-pvf.py` 的 `ScriptText.decompile` 和 `ScriptText.compile`。
- 浮点数、整数和显式类型标记是不同 token。不要把 `1.0` 改写成 `1`，也不要删除 `{1=...}`、`{3=...}`、`{6=...}` 或 `{8=...}` 的类型信息。原样保留反引号和转义序列。
- 不要在反编译脚本中加入 Markdown、说明文字或 `//` 注释。编译器不会把这些内容统一当作注释。手册代码块是阅读摘录，不可整段覆盖原文件。
- `.str` 使用 `键>值` 行格式，不使用 #PVF_File 头。回包器参照原条目的编码写回。格式占位符及键本身应与调用方一致。
- `.nut`、部分 `.txt` 和二进制 `.ani` 等可能原样输出。不能依据扩展名强制用 UTF-8 另存为，也不能给原样文件加反编译脚本头。原样脚本中的非 UTF-8 注释字节需要保留。

### 文本、字符串与资源引用

- 脚本中的本地化链接保存模块编号和键。链接内显示的中文只是解包阅读辅助，编译器会忽略该段显示值。修改可见文字应定位相应 `.str` 的既有键值。
- 编译器只查源封包已有字符串表。添加新标签、新枚举名、新键或新路径字符串可能报字符串表缺失，当前工具不会自动扩充全局字符串表。
- `.lst` 的结构不统一。资源列表通常是 ID 与路径交替，名称反查表可能是名称与 ID 交替。叶子手册标明的实际样本形状优先于扩展名猜测。
- ID 必须在所属资源系统中查证。怪物 ID、NPC ID、技能 ID、物品 ID、被动对象 ID 和界面控件编号不能只因数值相同就互换。
- 同一标签可能出现在不同职业、难度、事件或嵌套块中。修改前先定位父块及目标记录，再改具体参数。空字符串、负值、终止标记和空段都可能是格式的一部分。

### 当前回包器的能力边界

`dnf-pvf.py` 的 `build_archive` 遍历源封包目录树，`packed_bytes` 按原条目类型编码修改内容。

- 修改已有路径的条目会写回。没有变化的条目复用原始内容。
- 删除或重命名已有磁盘文件会让对应原条目从新目录树移除。
- 在解包目录中新增文件不会自动增加封包条目。改列表指向新文件也不等于新增资源已经入包。
- 编译上下文来自源封包。不能依赖同轮修改磁盘上的字符串表或模块索引，让其他脚本立即采用新的编译上下文。
- 回包时的语言参数应与解包时一致。当前解包文件来自默认简体转换，使用 `--lang zh-hans`。

### 每次修改的执行顺序

1. 根据目标玩法进入叶子手册，查明实际被引用的条目、父块和字段。保存待改文件原字节及其修改前摘要，记录参数现值。
2. 对照样本确认类型、值数量、单位证据和关联 ID。未知位置不能通过猜测列号批量替换。每次只改一个能独立核对的目标。
3. 保留原格式和所有不相关内容，尤其是 CRLF、制表符、浮点类型和原样文件编码。核对改动仅发生在预期记录中。
4. 重新打包到 rebuild，检查改动数量与预期一致，并确认没有意外缺失条目。已有 output 中若有其他修改，计数需逐项说明。
5. 从回包文件重新读取目录树及实际目标条目，比较新值、引用与未改字段。最后实机测试该功能的正常路径、边界条件及相关模式。

```sh
python3 dnf-pvf.py Script.pvf --pack -i output -o rebuild --lang zh-hans
```

`--verify` 仅对传入 PVF 的脚本做解码与编码往返，不读取改过的 output。不能把对原始 Script.pvf 的 `--verify` 通过当作磁盘修改的验收。

下面的只读示例直接检查回包内的账号仓库条目。其他目标应换成自己实际修改的封包路径。

```python
from pathlib import Path
import runpy

pvf = runpy.run_path("dnf-pvf.py")
data = Path("rebuild/Script.pvf").read_bytes()
header, pack_start, entries = pvf["read_index"](data)
by_path = {entry[1].lower(): entry for entry in entries}
lang = pvf["LANGUAGES"]["zh-hans"]
scripts = pvf["load_script_context"](data, pack_start, by_path, lang)
entry = by_path["etc/accountcargo.etc"]
payload = pvf["entry_bytes"](data, pack_start, entry)
print(scripts.decompile(payload))
```
